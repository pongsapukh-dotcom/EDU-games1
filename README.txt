EduGame V10 — แก้ให้เล่นได้จริง + สมัคร/เก็บข้อมูลได้จริง
=========================================================

วิธีเปิดเล่น (สำคัญ — อย่าดับเบิลคลิก index.html ตรง ๆ)
-------------------------------------------------------
1) Windows: ดับเบิลคลิก start.bat      Mac/Linux: รัน ./start.sh
   แล้วเบราว์เซอร์จะเปิด http://localhost:8000  (ต้องติดตั้ง Python)
2) ถ้าจะให้นักเรียนต่างเครื่องเข้าห้อง ต้องอัปโหลดทั้งโฟลเดอร์ขึ้นโฮสต์ที่เป็น HTTPS
   (เช่น Netlify Drop, GitHub Pages, Cloudflare Pages) — เบราว์เซอร์จะอนุญาตกล้องเฉพาะ
   https:// หรือ http://localhost เท่านั้น

แก้เพิ่มใน V10.1 (ระบบกล้อง)
---------------------------
- ขอสิทธิ์/เปิดกล้องครั้งเดียวแล้วส่งภาพเข้า AI ตรวจจับมือเอง (เลิกใช้ Camera ของ MediaPipe ที่ขอกล้องซ้ำ
  ทำให้บางเครื่อง/มือถือขึ้น "กล้องถูกใช้งานอยู่" หรือจอดำเงียบ ๆ)
- ตรวจว่าโมเดลมือโหลดสำเร็จจริงก่อนเริ่มเล่น ถ้าไม่ได้ให้สลับเป็นโหมดเมาส์/สัมผัสพร้อมข้อความ
- ถ้า AI หยุดทำงานกลางเกม (ส่งเฟรมพลาดติดกัน) เกมฟันผลไม้/เกราะเวหาสลับเป็นโหมดเมาส์ให้เอง
- เกมยิงธนู: เวลารอโหลด AI (30 วิ) เริ่มนับหลังเปิดกล้องแล้ว ไม่นับเวลาที่รอกดอนุญาต
- ปิดกล้องทันทีเมื่อสลับไปโหมดเมาส์

สิ่งที่แก้ใน V10
----------------
1) ทุกเกมเล่นได้แน่นอน
   - ถ้าเปิดกล้องไม่ได้ / ไม่อนุญาตกล้อง / โหลด AI ตรวจจับมือไม่ได้ เกมจะไม่ค้างอีกต่อไป
     แต่แจ้งสาเหตุเป็นภาษาไทย แล้วสลับเป็นโหมดเมาส์/นิ้วสัมผัสอัตโนมัติ
   - มีปุ่ม "เล่นด้วยเมาส์/สัมผัส (ไม่ใช้กล้อง)" ในทุกเกม
       ฟันผลไม้   : กดค้างแล้วลากผ่านผลไม้
       เกราะเวหา   : เลื่อนเมาส์ไปที่โดรนคำตอบแล้วค้างไว้ 0.75 วินาที
       ยิงธนู      : กดค้างแล้วลากถอยหลังเพื่อดึงสาย ปล่อยเพื่อยิง (ธนูพุ่งทิศตรงข้ามกับที่ลาก)
   - ไลบรารี (three.js / MediaPipe) โหลดแบบมีตัวสำรอง: โฟลเดอร์ vendor/ -> jsDelivr -> unpkg
     เกราะเวหาไม่ต้องใช้ Tailwind CDN อีกต่อไป
   - ชุดคำถามที่ส่งมาก่อนเกมโหลดเสร็จ (ยิงธนู) ไม่หายอีกแล้ว
   - เปิดเกมโดยตรงโดยไม่มีชุดคำถาม จะใช้คำถามตัวอย่างให้

2) สมัครสมาชิกและเก็บข้อมูลได้จริง (ทำงานได้ทั้งมีและไม่มี Supabase)
   - สมัคร/เข้าสู่ระบบ: ลองบนคลาวด์ (Supabase) ก่อน ถ้าเชื่อมต่อไม่ได้จะสร้าง "บัญชีในเครื่อง"
     ให้ทันที (รหัสผ่านเข้ารหัส PBKDF2 ก่อนเก็บ) ล็อกอินค้างไว้ได้ ไม่หายเมื่อรีโหลด
   - ชุดคำถามและรูป: เก็บบน Supabase ถ้าตั้งค่าตารางแล้ว ไม่เช่นนั้นเก็บในเบราว์เซอร์เครื่องนี้
     (แยกตามบัญชี) พร้อมข้อความแจ้งบนหน้าสร้างคำถาม
   - ปุ่ม "สำรองข้อมูล / นำเข้า" ที่หน้าเลือกเกม ใช้ย้ายชุดคำถามข้ามเครื่องหรือกันข้อมูลหาย
   - ข้อจำกัด: บัญชี/ข้อมูลแบบ "ในเครื่อง" อยู่ในเบราว์เซอร์นั้นเท่านั้น
     ล้างข้อมูลเบราว์เซอร์แล้วจะหาย และไม่ตามไปเครื่องอื่น ถ้าต้องการให้ตามไปทุกเครื่อง
     ให้ตั้งค่า Supabase ตามด้านล่าง

ตั้งค่า Supabase (เพื่อให้บัญชี/ข้อมูลอยู่บนคลาวด์จริง และห้องเรียนข้ามเครื่อง)
----------------------------------------------------------------------------
1) เปิด Supabase Dashboard ของโปรเจกต์ > SQL Editor > วางเนื้อหาไฟล์ supabase-setup.sql > Run
   (สร้างตาราง question_sets + สิทธิ์ครูแต่ละคน + ที่เก็บรูป question-images)
2) Authentication > Providers > Email = เปิด
   - อยากให้สมัครแล้วเข้าได้ทันที: ปิด "Confirm email"
   - ถ้าเปิดไว้ ผู้สมัครต้องกดลิงก์ยืนยันในอีเมลก่อนเข้าสู่ระบบ
3) Authentication > Sign In / Providers > เปิด "Allow anonymous sign-ins" (สำหรับปุ่มผู้ทดสอบบนคลาวด์)
4) ใส่ url และ publishableKey ของคุณใน supabase-config.js (ใส่ของโปรเจกต์เดิมไว้แล้ว)
   ห้องเรียนเรียลไทม์ใช้ Supabase Realtime Broadcast ไม่ต้องสร้างตารางเพิ่ม

ให้ใช้งานแม้เน็ตบล็อก CDN (ไม่บังคับ)
-----------------------------------
รัน  python3 download-libs.py  ครั้งเดียว (ตอนที่ออนไลน์) จะดาวน์โหลดไลบรารีมาเก็บใน vendor/
เกมจะใช้ไฟล์ในเครื่องก่อนเสมอ

วิธีเล่นแบบห้องเรียน
-------------------
ครูเข้าสู่ระบบ > สร้างชุดคำถาม > เลือกเกม > "สร้างห้องให้นักเรียน" > ส่งลิงก์/รหัส 6 หลัก
นักเรียนใส่ชื่อ > ครูกดเริ่มเกม > ครูเห็นคะแนนสด
(ทดสอบในเครื่องเดียว: เปิดลิงก์ห้องในแท็บใหม่ของเบราว์เซอร์เดิม)

ไฟล์ในโฟลเดอร์
--------------
index.html / script.js / style.css      หน้าเว็บหลัก ระบบสมัคร สร้างคำถาม ห้องเรียน
edugame-common.js / edugame-libs.js     ตัวช่วยกลาง / ตัวโหลดไลบรารีและตรวจกล้อง
realtime.js                             ห้องเรียนเรียลไทม์
ar_fruit_slash_game.html, cyber_sky_aero_intercept.html, ar_archery_thai_verb_game_full_sfx.html   3 เกม

start.bat / start.sh / download-libs.py ตัวช่วยเปิดเซิร์ฟเวอร์ในเครื่อง / โหลดไลบรารี

V10.3 PATCH NOTES (2026-10-31)
============================================================
1) Cyber Sky question entrance animation:
   - Each question appears large in the center of the screen.
   - It smoothly scales down to a compact panel near the top.
   - The compact question panel disappears after a short interval.
   - The panel does not capture pointer input, so answer targets remain usable.

2) Camera / iframe permission:
   - The game iframe now explicitly requests camera, microphone and fullscreen
     permissions using allow="camera *; microphone *; fullscreen *".
   - Camera errors in Cyber Sky now display the browser error name and clearer
     guidance, including iframe / Permissions Policy restrictions.
   - EduLibs checks whether the current document is blocked from camera by
     Permissions Policy before requesting getUserMedia.

IMPORTANT CAMERA TEST:
   - Camera access requires HTTPS or localhost. Opening the site over ordinary
     http:// on another device/IP address will normally block getUserMedia.
   - In the browser address bar, set Camera permission to Allow, then reload.
   - If hosted behind a server/CDN, make sure its Permissions-Policy response
     header does not disable camera. The parent page must allow camera for the
     game iframe as well.
   - The package has passed JavaScript syntax checks, but a real webcam and
     cross-device browser session were not available in this build environment.
     Therefore camera operation is NOT claimed as fully verified.

V10.4 PATCH NOTES (2026-10-31)  — ดรอปตัวเลือกเป็นระลอก + แก้ระบบกล้อง
============================================================
เกราะเวหาไซเบอร์ และ เกมยิงธนู: ตัวเลือกลงมาต่อเนื่องเหมือนเกมฟันผลไม้
  - ทุก ๆ ระลอก (เกราะเวหา ~1.8 วิ / ยิงธนู 1.5 วิ) จะปล่อย "ตัวเลือกครบทุกอัน" ลงมาใหม่
    ความเร็วตกต่างกันทีละตัว เห็นหลายสิบเป้าบนจอพร้อมกัน (เดิม 3-4 เป้าครั้งเดียวต่อข้อ)
    ทุกระลอกมีครบทุกตัวเลือก จึงไม่เฉลยว่าอันไหนถูกจากจำนวนที่ลงมา
  - เกมยิงธนูใช้ตัวเลือกครบสูงสุด 4 ตัว (เดิมตัดเหลือ 3) และโซนที่เป้าลงมากว้างขึ้นเป็นครึ่งซ้ายของจอ
  - เกราะเวหา: ตัวเลือกที่ไม่ได้กรอก (ว่าง) จะไม่ถูกปล่อยลงมาเป็นโดรนเปล่าอีก
  - กติกาเดิมคงไว้: เกราะเวหา = ล็อกเป้า 0.75 วิ ถูกได้คะแนนคูณคอมโบ / ผิดตัดคอมโบแล้วไปข้อต่อไป / เวลา 15 วิ
    ยิงธนู = ยิงถูก +10 / ยิงผิด -5 / ถูกลูกธนูปักขอบจอ
  - สิ่งเดียวที่ต้องปรับ: กติกา "คำตอบที่ถูกตกพื้น -5" ใช้ไม่ได้เมื่อมีคำตอบลงมาตลอด
    จึงเปลี่ยนเป็นนับเวลาข้อละ 20 วิ (มีตัวเลขใน HUD) หมดเวลาโดยไม่ยิงถูก = -5 แล้วไปข้อต่อไป
    ปรับค่าได้ที่ ROUND_SECONDS / WAVE_INTERVAL / FALL_SPEED_MIN / FALL_SPEED_MAX ในไฟล์เกมยิงธนู
    และ WAVE_EVERY / FALL_MIN / FALL_MAX ในไฟล์เกราะเวหา

แก้ระบบกล้อง
  - เกราะเวหา: พิกัดมือเดิม "ไม่กลับด้าน" ทั้งที่ภาพกล้องถูกกลับด้าน ทำให้วงเล็งขยับสวนทางกับมือ
    ตอนนี้กลับด้านถูกต้อง และคำนวณชดเชยการครอบตัดภาพ (object-fit: cover) ด้วย
    (เกมฟันผลไม้ก็ใช้การคำนวณชุดเดียวกัน จอที่สัดส่วนไม่ใช่ 16:9 จะเล็งตรงตำแหน่งนิ้วขึ้น)
  - เกราะเวหา: ภาพกล้องเดิมโปร่ง 24% จนดูเหมือนกล้องไม่ติด ปรับให้เห็นชัดขึ้น (62%)
  - เกมยิงธนู: ขออนุญาต/เปิดกล้องก่อน แล้วค่อยโหลด AI (เดิมโหลด AI ก่อน กล่องขออนุญาตกล้องจึงมาช้า
    หรือไม่ขึ้นเลยถ้าโหลดไลบรารีไม่ได้) และถ้าโหลด AI ไม่ได้จะปิดกล้องคืนให้
  - ทุกเกม: ถ้ากล้องหลุดหรือภาพค้างเกิน 8 วินาทีระหว่างเล่น จะสลับเป็นโหมดเมาส์/สัมผัสให้เอง
    โดยเล่นต่อจากเดิม ไม่รีเซ็ตคะแนน (เดิมเกมฟันผลไม้จะเริ่มเกมใหม่)
  - ทุกเกม: กด "เล่นอีกครั้ง" หลังเคยสลับเป็นโหมดเมาส์ จะลองเปิดกล้องใหม่ได้จริง (เดิมค้างโหมดเมาส์)
  - ข้อความ error ของกล้องชัดขึ้น เช่น กล้องเปิดแต่ไม่มีภาพส่งมา

ผลการทดสอบ

    เปิดกล้อง/สลับโหมด/ล็อกเป้า/ฟัน/ยิงถูก/หมดเวลา/ตัวเลือกว่าง ผ่านทั้งหมดโดยไม่มี error
  - ยังไม่ได้ทดสอบกับกล้องจริง, ไลบรารี MediaPipe จริงจาก CDN, และการแสดงผล 3D จริงของเกมยิงธนู
    ต้องลองบนเครื่องจริงผ่าน https:// หรือ http://localhost
